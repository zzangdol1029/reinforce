## [S1] 표지 — 0:00~0:20

안녕하세요. 산업인공지능학과 김완수입니다. 제가 발표할 주제는 **"강화학습 기반 Worker Thread Pool 동적 튜닝"** 입니다.

한 문장으로 정리하면, 서버 대수를 늘릴 수 없는 운영 환경에서 트래픽 변화에 맞춰 스레드 풀 크기를 자동으로 조절하는 정책을, DQN과 PPO로 학습하고 룰 기반 정책과 비교한 프로젝트입니다.

## [S2] 목차 — 0:20~0:35

## [S3] 프로젝트 개요 — 0:35~1:05

먼저 프로젝트를 What, Why, How로 정리했습니다.

**무엇을** 하느냐, 한 번 튜닝하고 고정해 둔 worker thread 수를 트래픽에 따라 늘리고 줄이는 **동적 튜닝 정책**을 만드는 것입니다. **왜** 하느냐, 트래픽은 하루 주기로 출렁이는데 thread는 고정값이라, 부족하면 SLA를 위반하고 과하면 자원을 낭비하기 때문입니다. **어떻게**, DQN과 PPO로 조절 정책을 학습하고 실무 표준인 룰 기반·고정 설정과 정량 비교합니다.

핵심 도전은, **thread를 무작정 늘리면 오히려 느려지는 비단조 용량 곡선** 때문에 단순 임계값 룰로는 부족하다는 점입니다. 그래서 평소엔 기본값을 유지하다 트래픽 상승 조짐에 선제 증설하고 피크가 지나면 복귀하는, 그 운영 정책을 학습으로 구현하는 것이 목표입니다.

## [S4] 배경 — worker thread pool이란 — 1:05~1:30

용어를 먼저 맞추겠습니다. worker thread pool은 동시에 요청을 처리하는 **일꾼 스레드의 묶음**이고, 그 크기 c가 곧 동시 처리 능력입니다. 그림처럼 요청이 들어오면 thread가 처리하고, thread가 다 차면 대기 큐에서 기다립니다.

스레드가 너무 적으면 요청이 큐에서 밀려 지연이 커지고, 너무 많으면 컨텍스트 스위칭과 메모리 오버헤드로 오히려 느려집니다. **이 프로젝트가 조절하는 대상이 바로 이 풀 크기 c**입니다.

## [S5] 적용 문제 ① — 자원은 항상 어긋난다 — 1:30~2:00

제가 푼 문제입니다. MSA 서비스의 트래픽은 하루 주기로 출렁이고, 오전·저녁 피크에 예고 없는 버스트까지 끼어듭니다. 그런데 현장의 thread pool 크기는 보통 **한 번 튜닝하고 고정**해 둡니다.

자원이 부족하면 요청이 큐에 쌓여 응답 지연이 폭증하고 SLA를 위반합니다. 반대로 스레드가 남으면 메모리와 컨텍스트 스위칭이 낭비됩니다. 두 비용은 트레이드오프 관계이고, 게다가 적정 자원량이 트래픽에 따라 계속 움직입니다. 그래서 **"항상 넉넉히"가 답이 아니라**, 트래픽을 보면서 실시간으로 조절하는 정책이 필요합니다.

## [S6] 용어 설명 — SLA · 큐잉 이론 — 2:00~2:25

두 가지 핵심 용어만 짚겠습니다. **SLA는 서비스가 지켜야 할 성능 약속**으로, 이 프로젝트에서는 평균 응답 지연 200ms 이하로 정했습니다. 이걸 어기면 SLA 위반이고, 보상에서 가장 무거운 페널티를 받습니다.

**큐잉 이론**은 요청이 줄 서서 처리되는 시스템의 대기·지연을 분석하는 이론입니다. 도착률 λ, 처리율 μ, 처리기 수 c, 그리고 이용률 ρ는 λ를 처리 용량으로 나눈 값입니다. 핵심 직관 하나만 기억하시면 됩니다 — **이용률 ρ가 1에 가까워지면 대기 지연이 급격히 폭발**합니다. 본 시뮬레이터는 이 M/M/c 모델을 기반으로 합니다.

## [S7] 왜 강화학습인가 — 2:25~2:55

강화학습을 쓴 이유는 네 가지입니다. 첫째, 지금의 스레드 조절이 미래의 backlog에 영향을 주는 **순차적 의사결정** 문제입니다. 둘째, 대응이 늦으면 한동안 지연이 지속되는 **지연된 보상** 구조라, 피크 전 선제 대응이 이득입니다. 셋째, 최적점이 트래픽에 따라 계속 움직입니다. 넷째, **보상 함수로 운영 목표를 직접 표현**할 수 있습니다. 이 문제를 오른쪽처럼 MDP로 옮겼습니다 — 상태는 트래픽·이용률·지연·자원량, 행동은 thread를 4개 줄이거나 유지하거나 4개 늘리는 세 가지입니다.

## [S8] 인스턴스 고정 환경의 유일한 동적 자원 — 2:55~3:25

운영 환경의 제약을 말씀드리면, **인스턴스 수가 고정**입니다. 온프레미스라 수평 확장이 불가능해서 일반적인 인스턴스 오토스케일링을 쓸 수 없습니다. 그래서 주어진 인스턴스 안에서 조절 가능한 자원이 **Undertow의 worker thread pool**이고, 재기동 없이 런타임으로 풀 크기를 바꿀 수 있습니다.

여기서 중요한 건, 코어 수와 worker thread가 1대1이 아니라는 점입니다. worker는 DB나 외부 호출로 자주 대기하기 때문에 그 사이 코어가 놀지 않도록 코어보다 많이 둡니다. 다만 무작정 늘리면 컨텍스트 스위칭으로 역효과라 **최적점이 존재**합니다. 그 최적점이 트래픽에 따라 움직이니, 실시간으로 추적하는 게 본 프로젝트입니다.

## [S9] 모델 — 시뮬레이터 (M/M/c 근사) — 3:25~3:55

강화학습은 수만 Step의 시행착오가 필요하기 때문에, 실제 서버 대신 큐잉 이론 기반 시뮬레이터를 만들어 학습했습니다. 하루를 300 Step으로 설정하고, 랜덤 버스트로 트래픽 양이 매 에피소드마다 다르게 발생하도록 구성하였습니다.

트래픽은 두 가지 요소를 합산하여 생성하였습니다. 일 주기 패턴과 랜덤 버스트를 합하여 최종 트래픽이 되도록 하였습니다. 

핵심은 두 가지입니다. 이용률 p가이 1에 가까워지면 대기시간이 비선형으로 폭증한다는 것, 그리고 과부하로 처리 못 한 요청은 **backlog로 누적**되어 다음 step의 지연을 키운다는 것입니다. 오른쪽 응답시간 식에 이 두 성질이 들어 있습니다. 덕분에 "한 번 밀리면 한동안 느려지는" 실제 서버 거동을 재현합니다. 트래픽 패턴이 매 에피소드마다 변경되므로, 에이전트가 특정 패턴을 암기하는 것이 불가능합니다.

## [S10] 모델 — Agent·Environment 구조와 상태 — 3:55~4:30

강화학습 기본 구조는, 에이전트가 상태를 보고 행동을 선택하면 환경 시뮬레이터가 다음 상태와 보상을 돌려주는 루프입니다. 에이전트의 정책망은 2층 128 MLP이고, 행동은 thread −4·유지·+4 세 가지입니다.

에이전트가 관측하는 **상태는 6차원**입니다. 현재 트래픽 λ, 그 변화량으로 피크가 오는 중인지 보고, 이용률 ρ로 큐 폭증 위험을 보고, 지연과 SLA 비율로 품질을 보고, 현재 스레드 수, 그리고 **backlog를 상태에 포함**시켰습니다.
State = [λ, Δλ(현재λ - 이전λ), ρ(λ[서버에서 들어오는 요청속도 : 80 req/s] /(c[서버대수]×μ[서버가 처리하는 요청 속도: 60 req/s])), 응답시간, SLA 비율, 스레드 수, backlog]
 과거의 여파를 상태에 담아야 MDP가 성립하기 때문입니다. 보상 변수는 SLA 초과, 증설분, 과소, 행동 변경 네 가지인데, 다음 두 장에서 자세히 보겠습니다.

## [S11] 모델 — 보상 설계 — 4:30~5:05

보상 설계가 정책의 성격을 결정합니다. 네 가지 상황으로 보시면, SLA를 지키며 기본값 16을 유지하면 페널티 0으로 가장 좋습니다. 트래픽이 오를 때 선제 증설하면 증설분만 소액 비용이 드는데, **SLA 위반 페널티보다 훨씬 싸기 때문에 피크엔 증설이 이득**입니다. 반대로 대응에 실패해 평균 지연이 SLA를 넘으면 가장 큰 페널티를 받습니다. 즉 SLA 준수가 최우선임을 학습합니다. 기본값 밑으로 줄이거나 너무 자주 바꾸는 것도 소액 페널티로 억제합니다.

결과적으로 보상이 유도하는 행동은 **평소엔 기본값 유지, 피크엔 선제 증설, 끝나면 복귀**입니다.

## [S12] 모델 — 보상 변수 상세 — 5:05~5:30

같은 보상 함수를 네 항으로 분해한 표입니다. 핵심은 **가중치 비율**입니다. SLA 위반이 1.0으로 가장 무겁고, 증설 비용 0.30과 과소 0.2가 중간, 진동 페널티가 0.02로 가장 가볍습니다. 이 1.0 ≫ 0.30 ≫ 0.02라는 비율이 그대로 운영 우선순위, 즉 **SLA가 비용보다, 비용이 안정성보다 우선**이라는 정책 철학을 표현합니다. 네 항이 동시에 0이 되는 지점, SLA를 지키며 thread 16을 유지하는 상태가 최고 보상입니다.

## [S13] 모델 — MDP 정의 · 비단조 용량 — 5:30~6:05  ★핵심

MDP를 한 장으로 정리했는데, 핵심 차이는 **용량이 비단조**라는 점입니다. 스레드가 32개까지는 병렬화 이득으로 용량이 늘지만, 그 이상에서는 컨텍스트 스위칭과 CPU 경합으로 오히려 용량이 줄어듭니다. 실측하면 **37개 부근에서 용량이 정점**을 찍고 그 이상은 역효과입니다.

그래서 "이용률 높으면 무조건 늘려라"는 룰 기반 정책은 이 함정에 빠질 수 있습니다. 에이전트는 이걸 피하면서 움직이는 최적점을 추적해야 합니다.

## [S14] 알고리즘 ① DQN — 6:05~6:35

첫 번째 알고리즘 DQN입니다. 가치 기반 off-policy로, 상태별 행동가치 Q를 학습합니다. 네트워크는 128, 128 두 층 MLP이고, **Experience Replay**로 10만 개 경험을 저장해 과거의 위기 상황을 반복 학습합니다. **Target Network**를 1,000 step마다 동기화해 학습을 안정화하고, **Double DQN**으로 Q값 과대추정을 완화했습니다. 탐험률 ε는 1.0에서 0.05까지 학습 절반 지점에 걸쳐 감소시킵니다. 
ε = 1.0  →  100% 랜덤 행동 (완전 탐험)
ε = 0.5  →  50% 랜덤, 50% 학습된 행동
ε = 0.05 →  5% 랜덤, 95% 학습된 행동 (거의 활용)
행동이 세 개뿐인 이산 공간(유지, 늘림, 줄임)이라 DQN이 잘 맞습니다.

## [S15] 알고리즘 ② PPO — 6:35~7:05

두 번째는 PPO입니다. 정책 경사 기반 on-policy로 정책을 직접 최적화합니다. **GAE**로 advantage 분산을 줄이고, 핵심인 **Clipped objective**로 정책 갱신 비율을 제한해서, 한 번의 업데이트로 정책이 급변하는 것을 막아 안정적으로 학습합니다. rollout 4096 step마다 10 epoch로 미니배치 학습을 합니다. 같은 문제에서 DQN과 어떻게 다르게 반응하는지가 관전 포인트입니다.

## [S16] 비교 베이스라인 — 7:05~7:25

비교 대상은 두 가지입니다. 하나는 **쿠버네티스 HPA가 실제로 쓰는 임계값 룰 기반** 정책으로, 이용률이 0.7을 넘으면 늘리고 0.3 밑이면 줄이며 진동 방지를 위해 쿨다운 3 step을 둡니다. 다른 하나는 스레드 16개로 고정한 정책입니다. 평가는 학습에 쓰지 않은 고정 시드 20 에피소드에서 네 정책을 동일 조건으로 비교했습니다.

## [S17~20] 프로그램 소스 — 7:25~8:10

소스 구조와 핵심 코드입니다. 디렉터리는 환경, 에이전트, 베이스라인, 학습, 평가로 구성했고, 딥러닝 라이브러리는 교재 DeZero를 써서 **MLP와 옵티마이저만 라이브러리, DQN·PPO 알고리즘 로직을 구현**했습니다.

환경의 step 함수는 행동에서 상태 전이, 보상까지 20줄 내외이고, 비단조 용량과 backlog 동역학이 핵심입니다. 비단조 용량 (capacity)은 스레드 수가 늘어도 처리율이 선형으로 증가하지 않으며, knee 초과 시 컨텍스트 스위칭 오버헤드로 인해 오히려 처리율이 감소하는 실제 서버 거동을 반영하였습니다.backlog(step) 동역학은 처리하지 못한 요청을 다음 Step으로 누적시켜 "한 번 밀리면 한동안 느려지는" 실제 서버 거동을 재현하였습니다.
DQN 학습 루프에서 s(현재상태), a(선택한 행동), r(받은 보상), s2(다음 상태), d(종료 여부) = self.buffer.sample(128)로 과거 경험 128개를 랜덤 추출합니다.
a_next = self.q(s2).data.argmax(axis=1) 으로 행동 선택합니다.
q_next = self.target(s2).data[arange(B), a_next]를 통해서 가치평가를 합니다.
y = r + gamma * (1 - d) * q_next 목표값이고 double dqn입니다.

그리고 PPO는 알고리즘을 코드 수준에서 직접 검증했다는 점만 봐주시면 됩니다.

# Double DQN learn() 함수 완전 분석

---

## 한 줄 요약

> 과거 경험을 꺼내서, 목표 Q값을 계산하고,  
> 현재 예측과의 차이를 줄이도록 신경망을 업데이트한다.

---

## 전체 흐름

```
[1] buffer.sample(128)
         ↓
    과거 경험 128개 무작위 추출

[2] a_next = self.q(s2).data.argmax(axis=1)
         ↓
    다음 상태에서 online 네트워크가 최선의 행동 선택

[3] q_next = self.target(s2).data[arange(B), a_next]
         ↓
    target 네트워크가 그 행동의 가치 평가

[4] y = r + gamma * (1 - d) * q_next
         ↓
    목표 Q값 계산 (정답지)

[5] q_sa = F.get_item(self.q(s), (arange(B), a))
         ↓
    현재 online 네트워크의 Q값 예측 (학생 답안)

[6] loss = F.sum((q_sa - y) ** 2) / B
         ↓
    정답과 예측의 차이 계산

[7] cleargrads → backward → clip_grads → update
         ↓
    신경망 가중치 업데이트

[8] step_count % 1000 == 0
         ↓
    target 네트워크 동기화
```

---

## 소스 코드

```python
def learn(self):
    s, a, r, s2, d = self.buffer.sample(128)

    # Double DQN: 선택은 online, 평가는 target
    a_next = self.q(s2).data.argmax(axis=1)
    q_next = self.target(s2).data[arange(B), a_next]
    y = r + gamma * (1 - d) * q_next

    q_sa = F.get_item(self.q(s), (arange(B), a))
    loss = F.sum((q_sa - y) ** 2) / B

    self.q.cleargrads()
    loss.backward()        # DeZero 자동미분
    clip_grads([self.q], 10.0)
    self.opt.update()      # Adam

    if self.step_count % 1000 == 0:
        self.target = copy.deepcopy(self.q)
```

---

## [1] Replay Buffer 샘플링

```python
s, a, r, s2, d = self.buffer.sample(128)
```

### Replay Buffer란?

```
에이전트가 환경과 상호작용하며 쌓은
(s, a, r, s2, d) 경험을 저장하는 메모리

매 Step마다 경험이 쌓이고
learn() 호출 시 128개를 랜덤 추출
```

### 각 변수 의미

| 변수 | 이름 | 의미 | 예시 |
|------|------|------|------|
| **s** | state | 현재 상태 | [λ=150, ρ=0.85, backlog=100, c=4] |
| **a** | action | 선택한 행동 | 2 (스레드 증설) |
| **r** | reward | 받은 보상 | -0.3 (SLA 위반 페널티) |
| **s2** | next state | 다음 상태 | [λ=150, ρ=0.70, backlog=50, c=8] |
| **d** | done | 종료 여부 | 0 (계속) / 1 (종료) |

### 왜 랜덤 샘플링인가?

```
순서대로 학습하면
s1→s2→s3 연속된 경험은 서로 높은 상관관계

→ 특정 패턴에 과적합 발생
→ 랜덤 샘플링으로 상관관계 제거
→ 학습 안정성 확보
```

---

## [2] online 네트워크 행동 선택

```python
a_next = self.q(s2).data.argmax(axis=1)
```

### 단계별 분석

```
self.q(s2)
→ online 네트워크에 다음 상태 s2를 입력
→ 모든 행동에 대한 Q값 출력
   shape : [128, 3]

   행동0    행동1    행동2
  [-0.5,    0.8,   -0.2]  ← 샘플 1
  [ 0.3,   -0.1,    0.9]  ← 샘플 2
  ...                      ← 샘플 128

.data
→ DeZero Variable에서 numpy 배열로 변환
→ gradient 계산 불필요한 부분이므로 분리

.argmax(axis=1)
→ 각 샘플에서 Q값이 가장 높은 행동의 index 선택
  [-0.5,  0.8, -0.2] → argmax = 1 (행동1이 최선)
  [ 0.3, -0.1,  0.9] → argmax = 2 (행동2가 최선)

a_next = [1, 2, ...]  shape : [128]
```

---

## [3] target 네트워크 가치 평가

```python
q_next = self.target(s2).data[arange(B), a_next]
```

### 단계별 분석

```
self.target(s2)
→ target 네트워크에 동일한 s2 입력
→ 모든 행동의 Q값 출력
   shape : [128, 3]

   행동0    행동1    행동2
  [-0.4,    0.7,   -0.1]  ← 샘플 1
  [ 0.2,   -0.2,    0.8]  ← 샘플 2
  ...

arange(B)
→ [0, 1, 2, ..., 127]
→ 128개 샘플의 index

[arange(B), a_next]
→ 각 샘플에서 online이 선택한 행동(a_next)의 Q값만 추출

샘플1 : a_next=1 → target Q값 0.7 추출
샘플2 : a_next=2 → target Q값 0.8 추출

q_next = [0.7, 0.8, ...]  shape : [128]
```

### 왜 target 네트워크가 평가하는가?

```
online이 선택 + online이 평가 (일반 DQN)
→ 자신이 선택한 행동을 자신이 좋게 평가
→ Q값 과대평가 발생

online이 선택 + target이 평가 (Double DQN)
→ 독립적인 네트워크가 평가
→ Q값 과대평가 방지
→ 학습 안정성 향상
```

---

## [4] 목표 Q값(y) 계산

```python
y = r + gamma * (1 - d) * q_next
```

### 각 항목 의미

| 항목 | 값 예시 | 의미 |
|------|------|------|
| **r** | -0.3 | 현재 Step에서 받은 즉각 보상 |
| **gamma** | 0.99 | 미래 보상 할인율 |
| **(1-d)** | 0 또는 1 | 에피소드 종료 시 미래 보상 차단 |
| **q_next** | 0.7 | 다음 상태의 기대 가치 |

### 케이스별 계산

```
에피소드 진행 중 (d=0)
y = -0.3 + 0.99 * (1-0) * 0.7
  = -0.3 + 0.693
  = 0.393

에피소드 종료 (d=1)
y = -0.3 + 0.99 * (1-1) * 0.7
  = -0.3 + 0
  = -0.3  (즉각 보상만 사용)
```

### gamma의 역할

```
gamma = 0.99

1 Step 후 보상  × 0.99¹  = 0.990
2 Step 후 보상  × 0.99²  = 0.980
10 Step 후 보상 × 0.99¹⁰ = 0.904
50 Step 후 보상 × 0.99⁵⁰ = 0.605

→ 가까운 미래일수록 현재 가치에 크게 반영
→ 먼 미래일수록 점점 작게 반영
```

---

## [5] 현재 Q값(q_sa) 계산

```python
q_sa = F.get_item(self.q(s), (arange(B), a))
```

```
self.q(s)
→ 현재 상태 s에 대한 모든 행동의 Q값
   shape : [128, 3]

F.get_item(..., (arange(B), a))
→ 실제로 선택했던 행동 a의 Q값만 추출
   shape : [128]

예시)
self.q(s) 출력:
행동0    행동1    행동2
[-0.5,   0.8,   -0.2]  ← 샘플 1, 실제 행동 a=1
[ 0.3,  -0.1,    0.9]  ← 샘플 2, 실제 행동 a=2

q_sa = [0.8, 0.9, ...]
        ↑      ↑
     행동1   행동2의 Q값 추출
```

### y와 q_sa의 역할

```
y    : 목표 Q값 (정답지) → gradient 계산 X
q_sa : 예측 Q값 (학생 답안) → gradient 계산 O
```

---

## [6] Loss 계산

```python
loss = F.sum((q_sa - y) ** 2) / B
```

```
MSE (Mean Squared Error)

loss = Σ(q_sa - y)² / 128

q_sa = [0.8,  0.9,  ...]  ← 예측값
y    = [0.39, 0.65, ...]  ← 목표값

차이 = [0.41, 0.25, ...]
제곱 = [0.17, 0.06, ...]
평균 = 0.115  ← loss

loss가 클수록  → 예측이 목표와 멀리 떨어져 있음
loss가 작을수록 → 예측이 목표에 수렴
```

---

## [7] 역전파 및 가중치 업데이트

```python
self.q.cleargrads()         # ① gradient 초기화
loss.backward()             # ② 자동미분
clip_grads([self.q], 10.0)  # ③ gradient clipping
self.opt.update()           # ④ 가중치 업데이트
```

### ① cleargrads()

```
이전 Step의 gradient가 남아있으면
현재 Step gradient에 누적되어 잘못된 업데이트 발생
→ 매번 초기화 필수
```

### ② loss.backward()

```
loss → q_sa → MLP 가중치 순으로 역전파

∂loss/∂q_sa = 2(q_sa - y) / B
∂loss/∂W    = ∂loss/∂q_sa × ∂q_sa/∂W

DeZero가 자동으로 계산
```

### ③ clip_grads(10.0)

```
gradient 크기 계산
→ 10.0 초과 시 강제로 10.0으로 클리핑

학습 초반 gradient가 폭발적으로 커질 수 있음
→ 클리핑으로 안정적인 업데이트 보장

gradient < 10.0  →  그대로 사용
gradient ≥ 10.0  →  10.0으로 축소
```

### ④ opt.update() : Adam

```
gradient를 바탕으로 가중치 업데이트

W = W - lr × gradient (단순 SGD)

Adam은 여기에 추가로
→ 과거 gradient 평균 (momentum)
→ 과거 gradient 제곱 평균 (adaptive lr)
을 활용하여 학습률을 자동 조절

→ 더 빠르고 안정적인 수렴
```

---

## [8] Target Network 동기화

```python
if self.step_count % 1000 == 0:
    self.target = copy.deepcopy(self.q)
```

```
online (self.q)      : 매 Step 업데이트 → 가중치 계속 변화
target (self.target) : 1000 Step마다 online 복사 → 고정

왜 고정이 필요한가?

목표값 y를 계산할 때 target 사용
→ target이 매 Step 바뀌면 y도 매 Step 바뀜
→ 쫓는 목표가 계속 움직이는 격
→ 학습이 발산할 수 있음

1000 Step 동안 target 고정
→ 안정적인 목표값 유지
→ 학습 수렴성 확보
```
